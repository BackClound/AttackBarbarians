## 2. 架构设计

### 2.1 分层架构（L0–L5）

```
┌─────────────────────────────────────────────────────────────┐
│  L5  Meta / LiveOps   Economy · Shop · DailyReward · Ads    │
├─────────────────────────────────────────────────────────────┤
│  L4  Presentation       UI · Audio · VFX · DamageNumber     │
├─────────────────────────────────────────────────────────────┤
│  L3  Progression        Upgrade · Talent · Equipment ·      │
│                         UpgradeCard · Save (run progress)    │
├─────────────────────────────────────────────────────────────┤
│  L2  Gameplay Content   Wave · Boss · SpecialEnemy · Map    │
├─────────────────────────────────────────────────────────────┤
│  L1  Combat Core        Player · Enemy · Damage · Projectile│
│                         · Collision · AutoAttack · Skill      │
├─────────────────────────────────────────────────────────────┤
│  L0  Foundation         Bootstrap · GameState · EventBus    │
│                         · ServiceLocator · Pool · Config      │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 依赖规则

1. L(n) 仅依赖 L(0..n-1) 的**接口、事件、配置**。  
2. 跨层通信优先 `GameEvents`，禁止 L0 引用 L3+ 具体类。  
3. 场景实体（Player/Enemy）通过 **Controller + Bridge** 接入系统层。  
4. 配置一律通过 `configId` 字符串引用，存档不存 Unity 对象引用。

### 2.3 核心设计模式

| 模式 | 应用 |
|------|------|
| Service Locator | `ServiceLocator` 注册/获取 Manager |
| 事件驱动 | `EventBus` + `GameEvents` 静态门面 |
| 状态机 | `GameStateMachine` 管理 `GameState` |
| Presenter | UI 面板只做刷新与回调，不拼 UI |
| 表驱动 | `*DataSO` + `ConfigDatabaseSO` |
| 对象池 | `PoolManager` 管理高频实例 |
| Singleton | `MonoSingleton<T>` / `SingletonHost<T>` |

### 3.3 游戏状态机

**路径**：`Assets/Scripts/Core/GameState.cs`、`GameStateMachine.cs`

| 状态 | timeScale | 典型触发 |
|------|-----------|----------|
| `Bootstrapping` | 1 | 启动 |
| `Playing` | 1 | 战斗中 |
| `WaveTransition` | 1 | 波次完成 |
| `UpgradeChoosing` | 0 | 三选一 |
| `Paused` | 0 | 用户暂停 |
| `GameOver` | 0/1 | 玩家死亡 |

**合法转换（摘要）**：

```
Playing → WaveTransition → UpgradeChoosing → Playing
Playing → UpgradeChoosing（升级事件）
Playing → Paused → Playing
Playing → GameOver
```

## 9. 非功能需求（工程）

| ID | 类别 | 规格 | 实现 |
|----|------|------|------|
| NFR-PERF-01 | 帧率 | 移动端目标 60fps；同屏 50+ 敌人 | `PerformanceManager` + `PerformanceBudgetSO` |
| NFR-PERF-02 | GC | 战斗 `Update` 避免 LINQ/装箱 | 代码规范，需 Profiler 验证 |
| NFR-PERF-03 | 池化 | 敌人/子弹/特效/飘字 | `PoolManager` ✅ |

## 13. 技术债与实现差距

|----|----------|----------|------|

| 旧 PRD 类名 | `MetaGameService`, `BattleRunController` | 已重构为新 Manager 体系 | 废弃引用 |
